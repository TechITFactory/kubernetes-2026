Before you start

  • Finish Module 1 first. You need Docker running. Step 14 runs the image pushed to Docker Hub in Module 1 (techitfactory/module1-demo-api:1.0.0, public).
  • Terminal: bash or zsh — macOS Terminal, Linux, or WSL2 on Windows.
  • Resources: give Docker at least 4 GB of memory. The cluster uses three containers.

Install kubectl and kind

Slides 13–14~5 min

Goal: Install the two tools for this module: kubectl (the Kubernetes CLI) and kind (runs a whole cluster inside Docker).

Run from: anywhere
macOS (Homebrew)
brew install kubectl kind
Windows (PowerShell) — then use WSL2 or Git Bash for the rest of the lab
winget install -e --id Kubernetes.kubectl
winget install -e --id Kubernetes.kind
Linux (x86-64) — for ARM, replace amd64 with arm64
curl -LO "https://dl.k8s.io/release/$(curl -Ls https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -m 0755 kubectl /usr/local/bin/kubectl

curl -Lo kind https://github.com/kubernetes-sigs/kind/releases/download/v0.33.0/kind-linux-amd64
sudo install -m 0755 kind /usr/local/bin/kind
Check all three tools
kubectl version --client
kind version
docker info --format '{{.ServerVersion}}'
Expected output
Client Version: v1.37.1
Kustomize Version: v5.8.1
kind v0.33.0 go1.26.7 linux/amd64
29.3.1
What just happened
  • kubectl is only a client. On its own it talks to nothing — we need a cluster next.
  • kind builds a real Kubernetes cluster where every node is a Docker container. That's why Docker from Module 1 must be running.
  • Your versions may be newer. Anything from kubectl v1.34 and kind v0.30 onward works for this lab.
Checkpoint
All three commands print a version, with no errors.

What just happened

Recognise the two classic errors

Terminal
kubectl get nodes --context does-not-exist
kubectl get nodes --server https://127.0.0.1:1 --request-timeout=5s 2>&1 | tail -1
Expected output
Error in configuration: context was not found for specified context: does-not-exist
The connection to the server 127.0.0.1:1 was refused - did you specify the right host or port?
What just happened
  • A context = a cluster + a user + a default namespace. Switching context changes where kubectl sends requests.
  • The same kubectl get pods showed different pods — only because the context's namespace changed. This is the #1 reason people think "my pods disappeared".
  • "Context was not found" means a typo in the context name. "Connection refused" means the address in kubeconfig is wrong, or the cluster is not running (slide 23).
Careful: Before any command that changes or deletes something, run kubectl config current-context. At work, the wrong context can mean the production cluster.
Checkpoint
You are back on kind-lab, and get-contexts shows the * next to it.

FormatBest for
-o widePeople — the normal table plus extra columns
-o nameScripts that loop over objects (node/lab-worker)
-o jsonpath=…Scripts that need one field
-o custom-columns=…Your own table, with exactly the columns you want

The control plane — spot what's missing
kubectl get pods -n kube-system --no-headers -o custom-columns=NAME:.metadata.name | grep -E 'apiserver|controller|scheduler|etcd'
Expected output
etcd-lab-control-plane
kube-apiserver-lab-control-plane
kube-controller-manager-lab-control-plane
kube-scheduler-lab-control-plane
What just happened
  • kube-proxy mode: iptables is still the default. nftables (stable since v1.33) scales better on big clusters, and ipvs is the older alternative. Some network plugins, such as Cilium, replace kube-proxy completely.
  • cgroups: the kubelet uses the systemd cgroup driver, like the container runtime. Since v1.35 the kubelet refuses to start on cgroup v1 unless you explicitly allow it — use hosts with cgroup v2 (every current Linux distribution and Docker Desktop).
  • Images: every core image comes from registry.k8s.io. The old k8s.gcr.io registry is frozen — if an old manifest still points there, update it.
  • The missing component: cloud clusters (EKS, GKE, AKS) run a fifth control-plane component, the cloud-controller-manager. It talks to the cloud API: it builds load balancers for LoadBalancer Services, sets node addresses, and removes nodes whose VM is gone. kind has no cloud, so there is none — in Module 4B you'll run cloud-provider-kind, which plays that role.
Note: On some Linux hosts docker info prints cgroup version: 1. Kubernetes v1.37 nodes will then only start with an explicit failCgroupV1: false kubelet setting — plan a move to cgroup v2.

Troubleshooting

kind create cluster fails with Cannot connect to the Docker daemon
Docker isn't running. Start Docker Desktop (or sudo systemctl start docker) and try again.
ERROR: failed to create cluster: node(s) already exist for a cluster with the name "lab"
A previous cluster is still there. Run kind delete cluster --name lab, then create it again.
The connection to the server localhost:8080 was refused
kubectl has no kubeconfig context. Check kubectl config get-contexts and run kubectl config use-context kind-lab.
No resources found in default namespace but you expected pods
You're in a different namespace or context. Add -n <namespace>, use -A for all namespaces, or check kubectl config get-contexts.
Pods stuck in ImagePullBackOff
The node can't download the image. Check the image name with kubectl describe pod <name>. For a Docker Hub image, check that the user name and tag exist on hub.docker.com; images only on your laptop need kind load docker-image.
Tab completion doesn't work for k
Install bash-completion and add the complete -o default -F __start_kubectl k line (Step 10).
Cluster creation is slow or times out on the first run
The first run downloads the ~1 GB node image. Give Docker at least 4 GB of memory in Docker Desktop settings.
kind load fails with ctr: content digest sha256:… not found
Docker 29 keeps images in its containerd image store: it downloads only your platform, but docker save still lists all of them, and kind's import looks for every one. Save just your platform and load the archive — that's what the pre-load commands at the top of this page do: docker save --platform "$(docker version --format '{{.Server.Os}}/{{.Server.Arch}}')" -o image.tar IMAGE then kind load image-archive image.tar --name lab. Images you built yourself (like module1-demo-api) load fine with kind load docker-image.
ERROR: unknown containerd config version: 4 from kind
Your kind binary is older than the node image. Install kind v0.33 or newer (Module 2, Step 1) and run kind version to check.
