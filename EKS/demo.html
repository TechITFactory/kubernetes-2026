The idea in plain words

EKS is Kubernetes where AWS runs the hard part. We describe the whole setup in Terraform files, run one command, and about twelve minutes later a cluster exists. Run another command and it is gone.

The control planeThe Kubernetes brain. AWS runs it. You pay about 10 cents an hour.
The worker nodesNormal EC2 servers that run your apps. You choose the size and how many (1 to 4 here).
The peopleIAM decides who may enter. A new employee is added to one group and gets the right access, with nothing installed in the cluster.

Three layers — what we actually deploy

LayerWhat growsWho decidesWhat we deploy
1. PodsCopies of your appHPA, watching CPU from metrics-servermetrics-server add-on (Terraform). The HPA itself is one kubectl autoscale command.
2. NodesEC2 machinesCluster Autoscaler, when Pods are PendingHelm chart + an IAM role with Pod Identity (autoscaler.tf)
3. LimitsHow far layer 2 may goYou, in Terraformmin_size = 1, desired_size = 2, max_size = 4 of t3.medium
Why min and max matter: the autoscaler may only move inside the range you set. min 1 stops it from shrinking to nothing; max 4 caps your bill if something goes wrong. The numbers in the playground are exactly the ones in variables.tf.

The rule to remember: nobody is added to the cluster by hand. People join an IAM group; the group may assume one role; the cluster maps that role to Kubernetes permissions through an access entry. Definitions
EKS
Elastic Kubernetes Service. AWS runs the Kubernetes control plane for you; you bring the worker nodes.
Terraform
A tool that builds cloud resources from text files. You describe what you want; it creates, changes and deletes to match.
Control plane
The cluster's brain: API server, etcd, scheduler. On EKS, AWS runs and patches it.
Node
One EC2 virtual machine that runs your Pods.
Managed node group
A group of nodes (an AWS Auto Scaling group) that EKS creates, patches and replaces for you.
min / desired / max
The smallest, the current and the largest number of nodes the group may have.
VPC
Your private network in AWS.
Subnet
A slice of the VPC in one availability zone. Public has a route to the internet; private does not.
NAT gateway
Lets private nodes reach the internet outward only.
IAM
AWS's system for users, groups, roles and permissions.
IAM role
An identity you assume temporarily. It has no password; people and services borrow it.
Access entry
The EKS setting that says "this IAM role gets these Kubernetes permissions".
kubeconfig
The file (~/.kube/config) that tells kubectl which cluster to talk to and how to log in.
HPA
Horizontal Pod Autoscaler: adds or removes Pods based on CPU.
Cluster Autoscaler
Adds or removes nodes when Pods cannot fit (Pending) or nodes sit empty.
Pending
A Pod that has been created but has no node with enough free CPU or memory yet.
Pod Identity
Gives a Pod its own AWS permissions without storing keys in the cluster.
Add-on
A system component (DNS, networking, metrics) that AWS installs and updates for you.

  • You need an AWS account and an IAM user that can create VPCs, EKS clusters and IAM roles (the lab used AdministratorAccess).
  • Install Terraform 1.6+, the AWS CLI, kubectl and Helm. Terminal: bash or zsh (macOS, Linux, WSL2).
  • Never put AWS keys in a file that goes to Git. We use environment variables, and the .gitignore in the lab blocks state files.
  • Always finish with Step 9. A forgotten cluster costs about $6 a day.

Creates: versions.tf — which Terraform and AWS provider versions to use
# Create versions.tf
cat > versions.tf <<'EOF'
terraform {
  required_version = ">= 1.6"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project   = var.cluster_name
      ManagedBy = "terraform"
    }
  }
}
EOF
Creates: variables.tf — the settings you may change (size, min/max nodes, version)
# Create variables.tf
cat > variables.tf <<'EOF'
variable "region" {
  description = "AWS region to deploy into"
  type        = string
  default     = "us-east-1"
}

variable "cluster_name" {
  description = "Name of the EKS cluster (also used to name the VPC and IAM roles)"
  type        = string
  default     = "demo-eks"
}

variable "kubernetes_version" {
  description = "Kubernetes version of the control plane"
  type        = string
  default     = "1.35"
}

variable "vpc_cidr" {
  description = "IP range of the VPC"
  type        = string
  default     = "10.0.0.0/16"
}

variable "node_instance_type" {
  description = "EC2 size of every worker node"
  type        = string
  default     = "t3.medium"
}

variable "node_min_size" {
  description = "Fewest worker nodes the node group may shrink to"
  type        = number
  default     = 1
}

variable "node_desired_size" {
  description = "Worker nodes created at the start"
  type        = number
  default     = 2
}

variable "node_max_size" {
  description = "Most worker nodes the node group may grow to"
  type        = number
  default     = 4
}
EOF
Creates: vpc.tf — the network: VPC, subnets, NAT gateway
# Create vpc.tf
cat > vpc.tf <<'EOF'
data "aws_availability_zones" "available" {
  state = "available"
}

locals {
  azs = slice(data.aws_availability_zones.available.names, 0, 2)
}

module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 6.0"

  name = var.cluster_name
  cidr = var.vpc_cidr
  azs  = local.azs

  # Two private subnets for nodes, two public subnets for load balancers and the NAT gateway
  private_subnets = [for i, az in local.azs : cidrsubnet(var.vpc_cidr, 4, i)]
  public_subnets  = [for i, az in local.azs : cidrsubnet(var.vpc_cidr, 8, 48 + i)]

  # One shared NAT gateway keeps the demo cheap (production: one per AZ)
  enable_nat_gateway = true
  single_nat_gateway = true

  enable_dns_hostnames = true
  enable_dns_support   = true

  # These tags tell Kubernetes which subnets to use for internet-facing and internal load balancers
  public_subnet_tags  = { "kubernetes.io/role/elb" = 1 }
  private_subnet_tags = { "kubernetes.io/role/internal-elb" = 1 }
}
EOF
Creates: eks.tf — the cluster, the node group, the add-ons, and who may enter
# Create eks.tf
cat > eks.tf <<'EOF'
module "eks" {
  source  = "terraform-aws-modules/eks/aws"
  version = "~> 21.0"

  name               = var.cluster_name
  kubernetes_version = var.kubernetes_version

  vpc_id     = module.vpc.vpc_id
  subnet_ids = module.vpc.private_subnets

  # API server reachable from your laptop. Production: restrict the CIDRs or use private only.
  endpoint_public_access = true

  # Access is managed with EKS access entries (no aws-auth ConfigMap)
  authentication_mode = "API"

  # Whoever runs terraform becomes cluster admin
  enable_cluster_creator_admin_permissions = true

  # Core add-ons, installed and kept up to date by AWS
  addons = {
    coredns                = {}
    kube-proxy             = {}
    vpc-cni                = { before_compute = true }
    eks-pod-identity-agent = { before_compute = true }
    metrics-server         = {}
  }

  # The worker nodes: an AWS-managed Auto Scaling group of EC2 instances
  eks_managed_node_groups = {
    default = {
      ami_type       = "AL2023_x86_64_STANDARD"
      instance_types = [var.node_instance_type]
      capacity_type  = "ON_DEMAND"

      min_size     = var.node_min_size
      desired_size = var.node_desired_size
      max_size     = var.node_max_size

      disk_size = 20
      labels    = { workload = "general" }
    }
  }

  # Pods on different nodes must reach each other on any port.
  # The module only opens ports 1025-65535 between nodes by default, so a Service on port 80 would time out.
  node_security_group_additional_rules = {
    ingress_self_all = {
      description = "Node to node, all ports and protocols"
      protocol    = "-1"
      from_port   = 0
      to_port     = 0
      type        = "ingress"
      self        = true
    }
  }

  # Extra people who may use the cluster (see access.tf for the role)
  access_entries = {
    developer = {
      principal_arn = aws_iam_role.developer.arn

      policy_associations = {
        # Read everything in the cluster
        view_all = {
          policy_arn   = "arn:aws:eks::aws:cluster-access-policy/AmazonEKSViewPolicy"
          access_scope = { type = "cluster" }
        }
        # Change things only in the "dev" namespace
        edit_dev = {
          policy_arn   = "arn:aws:eks::aws:cluster-access-policy/AmazonEKSEditPolicy"
          access_scope = { type = "namespace", namespaces = ["dev"] }
        }
      }
    }
  }
}
EOF
Creates: access.tf — the IAM group and role used to onboard people
# Create access.tf
cat > access.tf <<'EOF'
data "aws_caller_identity" "current" {}

# 1. The IAM role every developer will assume to reach the cluster
resource "aws_iam_role" "developer" {
  name = "${var.cluster_name}-developer"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Action    = "sts:AssumeRole"
      Principal = { AWS = "arn:aws:iam::${data.aws_caller_identity.current.account_id}:root" }
    }]
  })
}

# 2. A group: adding a person to it is the whole onboarding step
resource "aws_iam_group" "developers" {
  name = "${var.cluster_name}-developers"
}

# 3. The group may assume the role and look the cluster up (needed for "aws eks update-kubeconfig")
resource "aws_iam_group_policy" "developers" {
  name  = "eks-access"
  group = aws_iam_group.developers.name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = "sts:AssumeRole"
        Resource = aws_iam_role.developer.arn
      },
      {
        Effect   = "Allow"
        Action   = ["eks:DescribeCluster", "eks:ListClusters"]
        Resource = "*"
      }
    ]
  })
}
EOF
Creates: autoscaler.tf — the AWS permission the node autoscaler will use
# Create autoscaler.tf
cat > autoscaler.tf <<'EOF'
# Lets the Cluster Autoscaler Pod add and remove nodes, using EKS Pod Identity (no keys in the cluster)
resource "aws_iam_role" "cluster_autoscaler" {
  name = "${var.cluster_name}-cluster-autoscaler"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Action    = ["sts:AssumeRole", "sts:TagSession"]
      Principal = { Service = "pods.eks.amazonaws.com" }
    }]
  })
}

resource "aws_iam_role_policy" "cluster_autoscaler" {
  name = "cluster-autoscaler"
  role = aws_iam_role.cluster_autoscaler.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = [
          "autoscaling:DescribeAutoScalingGroups",
          "autoscaling:DescribeAutoScalingInstances",
          "autoscaling:DescribeLaunchConfigurations",
          "autoscaling:DescribeScalingActivities",
          "autoscaling:DescribeTags",
          "ec2:DescribeImages",
          "ec2:DescribeInstanceTypes",
          "ec2:DescribeLaunchTemplateVersions",
          "ec2:GetInstanceTypesFromInstanceRequirements",
          "eks:DescribeNodegroup"
        ]
        Resource = "*"
      },
      {
        Effect   = "Allow"
        Action   = ["autoscaling:SetDesiredCapacity", "autoscaling:TerminateInstanceInAutoScalingGroup"]
        Resource = "*"
      }
    ]
  })
}

# Connects the Kubernetes service account kube-system/cluster-autoscaler to the IAM role above
resource "aws_eks_pod_identity_association" "cluster_autoscaler" {
  cluster_name    = module.eks.cluster_name
  namespace       = "kube-system"
  service_account = "cluster-autoscaler"
  role_arn        = aws_iam_role.cluster_autoscaler.arn
}
EOF
Creates: outputs.tf — values printed at the end
# Create outputs.tf
cat > outputs.tf <<'EOF'
output "cluster_name" {
  value = module.eks.cluster_name
}

output "cluster_endpoint" {
  value = module.eks.cluster_endpoint
}

output "region" {
  value = var.region
}

output "developer_role_arn" {
  value = aws_iam_role.developer.arn
}

output "developers_group" {
  value = aws_iam_group.developers.name
}

output "connect_command" {
  value = "aws eks update-kubeconfig --region ${var.region} --name ${module.eks.cluster_name}"
}
EOF
What just happened
  • variables.tf is the control panel: node_min_size, node_desired_size and node_max_size decide how far the cluster can scale.
  • vpc.tf uses the community VPC module: 2 availability zones, 2 public and 2 private subnets, one NAT gateway.
  • eks.tf uses the community EKS module. authentication_mode = "API" turns on access entries, and access_entries is where the new-employee role is wired in.
  • node_security_group_additional_rules (in eks.tf) opens all ports between nodes. We found this by testing: by default only ports 1025–65535 are open, so a Pod on one node could not reach a Service on port 80 behind a Pod on another node (it just timed out).
  • Nothing is created yet. These are only text files.

Goal: Run a web app in two namespaces and give one of them a public address.
Terminal
# Create a namespace for development
kubectl create namespace dev
# Create a namespace for production
kubectl create namespace prod
# Run 2 copies of a web server in dev
kubectl -n dev create deployment web --image=public.ecr.aws/nginx/nginx:1.29-alpine --replicas=2
# Run 2 copies of the same web server in prod
kubectl -n prod create deployment web --image=public.ecr.aws/nginx/nginx:1.29-alpine --replicas=2
# Ask AWS for a public load balancer in front of the dev app
kubectl -n dev expose deployment web --port=80 --type=LoadBalancer
# Wait until the load balancer has an address
until kubectl -n dev get svc web -o jsonpath='{.status.loadBalancer.ingress[0].hostname}' | grep -q amazonaws; do sleep 5; done
# Save that address in a variable
LB=$(kubectl -n dev get svc web -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')
# Wait until the address answers (DNS takes a minute or two)
until curl -s -o /dev/null -m 5 http://$LB; do sleep 10; done
# Ask the app for its headers
curl -sI http://$LB | head -3
# Show where the Pods landed
kubectl get pods -A -l app=web -o wide

  • Terraform builds the VPC, the EKS control plane, a managed node group (1–4 × t3.medium), add-ons and the access roles from six small files.

  • terraform destroy removes everything, after you delete what Kubernetes created itself (load balancers).


Troubleshooting


"You must be logged in to the server (Unauthorized)" or "the server has asked for the client to provide credentials"
Your IAM identity has no access entry. Check you used --role-arn in update-kubeconfig and that you are in the developers group.


AccessDeniedException on aws eks update-kubeconfig
You are not in the IAM group yet, so eks:DescribeCluster is denied (step 8 shows this).


Pods stay Pending
No node has room. Run kubectl describe pod <name>. With the Cluster Autoscaler installed a node appears in about 2 minutes; if you are already at max_size, raise it.


terraform destroy hangs on the VPC or subnets
A load balancer made by Kubernetes still exists. Delete every Service of type LoadBalancer (kubectl delete svc …), wait a minute, then destroy again.


terraform destroy fails on the IAM group
The group still has members. Remove them first (step 9).


Surprise bill
Run aws eks list-clusters, aws ec2 describe-nat-gateways and aws elb describe-load-balancers in every region you used.
